# Private Beta Readiness Report

## Current classification

**Automated release gate passed. Overall private-beta recommendation: NO-GO
until the manual and guarded live blockers below are complete.**

This classification is deliberately stricter than "the app builds." Matrix
Coder is ready for internal staging and operator-led verification, but it
should not accept private-beta invitations yet.

## Automated results

- Vitest: PASS - 86 test files, 740 tests.
- Playwright: PASS - 10 desktop/mobile smoke tests.
- TypeScript: PASS - `yarn type-check`.
- Production build: PASS - Next.js 15.5.21, 31 pages generated.
- Dependency audit: PASS - 0 reported vulnerabilities across 246 audited packages.
- Benchmark certification dry run: PASS - all three core fixtures are
  selectable one at a time with the published fixed limits; no provider calls
  were made.
- Secret review: no committed real provider token or application secret was
  found. Matches are placeholders, synthetic tests, or database role names.

## Experimental

- Task-driven generation quality across broad application types.
- Real provider behavior under varied task sizes.
- Vercel live deployment and Stripe entitlement lifecycle.
- Full authenticated browser journey automation.

## Blocking live/manual proof

- Prove Supabase two-user RLS isolation for every project operation.
- Disable public Supabase signup or use an operator-controlled invite process.
  The application allowlist gate does not prevent direct public calls to
  Supabase Auth.
- Prove refresh/resume and cancellation during a live bounded task build.
- Prove Stripe test checkout, verified/idempotent webhook processing, customer
  portal, and past-due/grace behavior.
- Complete one guarded Vercel staging deployment and recovery check.
- Record an explicitly approved live result for
  `simple-business-website`; paid benchmarks remain manual only.
- Complete an authenticated keyboard and screen-reader review.
- Rehearse backup restore, migration rollback, incident communication, and
  credential rotation.
- Obtain professional review of all legal and privacy drafts.

## Supported first testers

- A very small operator-selected group using Next.js App Router projects.
- Testers who understand task-driven generation, Vercel deployment, and
  billing remain experimental.
- One active engineering build per project, using the fixed bounded limits:
  14 tasks, 20 AI requests, one repair per task, 30 minutes, 80 files, and
  450,000 generated bytes.

## Support and rollback

- Support uses operation IDs and the procedures in `SUPPORT_RUNBOOK.md`.
- AI, task builds, deployment, and checkout must remain independently
  disableable.
- Existing user projects remain readable/exportable during a service kill.
- Rollback requires a known release commit, database backup, migration review,
  and operator-owned status communication.

## Known limitations

- Policy text is a private-beta draft and is not legal advice.
- Browser automation covers public/auth/release smoke. Deep authenticated
  journeys rely on deterministic domain tests plus manual acceptance.
- Live provider, deployment, billing, and Supabase isolation results are not
  represented by the automated pass.
- The dependency graph uses managed security resolutions for transitive
  PostCSS and Sharp versions; these should be rechecked on each Next.js
  upgrade.
- Playwright reports non-blocking Next.js development warnings for image
  quality configuration and `allowedDevOrigins`.

## Go/no-go

**NO-GO for inviting private-beta users today.**

Proceed to a small controlled beta only after every blocking live/manual item
above has recorded evidence. Passing compilation, unit tests, and browser
smoke alone is not sufficient.
