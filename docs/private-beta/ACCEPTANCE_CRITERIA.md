# Private Beta Acceptance Criteria

These are targets, not claims about current results.

## Required before invitations

- No demonstrated cross-user project access.
- No secrets in project snapshots, exports, logs, telemetry, or client bundles.
- Validated work survives cancellation, refresh, and localized failure.
- Interrupted work restores as recoverable, never falsely complete.
- Task failures remain localized and bounded.
- Final completion requires evidence for every required Build Contract item.
- AI, task-build, deployment, checkout, rate, and plan limits are enforced server-side.
- Core automated suites and browser smoke pass.
- Supabase RLS receives a signed-in two-user manual audit.
- Stripe test mode proves checkout, verified webhook, idempotency, portal, and grace states.
- Vercel staging proves one guarded deployment and recovery from one mocked/controlled failure.
- At least the simple business benchmark has a reviewed live result.
- Known limitations and legal-review status are disclosed to every invited tester.

## Beta operating boundaries

- Invite-only users selected by the operator.
- Small projects using the supported Next.js App Router path.
- One active engineering build per project.
- Fixed benchmark limits: 14 tasks, 20 AI requests, one repair per task, 30 minutes, 80 files, 450,000 generated bytes.
- Operators can disable AI, task builds, deployment, or checkout independently.

## Public-launch blockers

- Professional legal/privacy review.
- Repeatable live benchmark evidence across all three core fixtures.
- Production monitoring and incident ownership.
- Confirmed backup/restore and migration rollback drills.
- Successful staged billing and deployment proofs.
